# Game Code Hub 业务培训教程：上货、采购、入库、履约全流程

> 适用对象：运营、采购、客服、财务、业务负责人
> 适用系统：Game Code Hub 后台管理控制台
> 访问入口：`https://tts-admin.sailson.com`
> 版本日期：2026-06-18
>
> 本教程按真实业务顺序编写：先把商品能卖清楚，再把库存备好，最后处理来单、异常和对账。
> 系统里所有金额默认使用**美分 cents**：`100` 表示 `$1.00`，`1000` 表示 `$10.00`。

## 0. 新人先看这一页

这页是给第一天上手的人用的。先按这里做，后面章节只是详细说明和截图。

### 0.1 每天只做 3 件事

1. 看 `看板`：确认「待发货」「今日失败」「低库存项」有没有异常。
2. 看 `订单`：如果有 failed 订单，点进详情看失败原因。
3. 看 `库存`：低库存就补货，补完后再重发失败订单。

能自己处理的情况：

| 看到什么 | 去哪里 | 怎么做 |
|---|---|---|
| `no_stock` | 订单详情的「手动补码」或 `采购单` / `库存` | 急单直接粘贴 CDK 补发；常规缺货先补货入库，再回订单详情点重发。 |
| `sku_not_mapped` | 订单详情的「去匹配 SKU」 | 系统会带入 TT 字段，补内部 SKU 和面额后再重发。 |
| 低库存 | `采购单` / `API 批量入库` | 手动采购或 API 批量入库。 |
| 供应商采购失败 | 订单详情的「看供应商采购」 | 看错误信息，确认 API 供应商、外部 SKU、币种和库存。 |

必须找负责人确认的情况：

- 要改 TikTok 商品售价。
- 要开启「库存不足时自动采购」。
- SKU 被「锁库存」。
- 要重发已经 `shipped` 的订单。
- 供应商给的卡密疑似重复、失效、被盗用。
- 财务金额和供应商账单对不上。

### 0.2 上新品照这 7 步

```text
1. TT 卖家中心上架商品
2. 后台 TT 商品中心同步并核对 seller_sku / product_id / sku_id / 售价
3. 在未匹配商品行点「去匹配」，系统会带入 TT 字段；已有映射时会直接打开现有记录
4. 选供货商：手动供应商 or API 供应商
5. 手动采购：建采购单 → 导入卡密
   API 采购：绑定外部 SKU → API 批量入库
6. 库存汇总确认 free 数量增加
7. 来测试单后看订单详情是否 shipped
```

### 0.3 订单失败照这 3 步

```text
1. 订单 → 搜订单号 → 点进详情
2. 看顶部「处理建议」和子单 failed_reason
3. 点建议按钮修原因 → 回订单详情点重发 → 刷新确认 shipped
```

不要连续点重发。点一次后等 3-10 秒刷新。

## 1. 系统是做什么的

Game Code Hub 是 TikTok Shop 虚拟商品履约后台，核心目标是：

1. 维护 TikTok 商品 SKU 与内部库存 SKU 的对应关系。
2. 采购并导入卡密库存，或者通过 API 供应商自动采购。
3. TikTok 来单后自动取码，通过 TikTok 虚拟商品发码接口发给买家。
4. 留下订单、库存、采购、供应商、财务、审计记录，方便排查和对账。

### 1.1 后台菜单和用途

| 菜单 | 业务用途 | 常用角色 |
|---|---|---|
| 看板 | 看今日订单、GMV、库存水位、失败订单 | 运营、负责人 |
| 订单 | 查订单、看履约状态、失败后重发 | 运营、客服 |
| 库存 | 看库存汇总、批次、单张卡状态、导入卡密 | 采购、运营 |
| TT 商品 | 从 TT Shop 同步已上架商品，检查哪些 TT SKU 还没匹配内部库存 | 运营、负责人 |
| SKU 映射 | 绑定 TT 商品和内部 SKU，配置售价、库存锁、API 采购链接 | 运营、采购 |
| 供货商 | 维护手动/API 供应商档案和 API 凭证 | 采购、负责人 |
| 采购单 | 新建 PO、记录付款、API 批量入库 | 采购、财务 |
| 供应商采购 | 查看 API 批量采购和实时采购记录 | 采购、客服 |
| 财务 | 看 GMV、毛利、应付、逾期应付 | 财务、负责人 |
| 内容创作 | 采集视频素材、查看素材库、生成短视频脚本和成片 | 运营、内容同事 |
| 用户管理 | 创建账号、分配角色、停用离职账号、重置密码 | 负责人 |
| 审计日志 | 查谁在什么时候做了什么操作 | 负责人、开发 |

看板重点：每天先看指标、低库存和失败订单。

![看板首页](assets/business-training/annotated/01-dashboard-overview-annotated.png)

### 1.2 角色和权限

| 角色 | 培训对象 | 主要能做什么 |
|---|---|---|
| `admin` | 负责人 | 全部功能、用户管理、审计日志、API 凭证、自动采购开关 |
| `ops` | 运营 | 看板、订单、库存、TT 商品、SKU 映射、供应商采购 |
| `purchase` | 采购 | 库存、TT 商品、SKU、供货商、采购单、API 批量采购 |
| `finance` | 财务 | 财务、采购单查看/付款、供货商只读 |
| `support` | 客服 | 订单查询/重发、库存/SKU/TT 商品只读、供应商采购只读 |

培训时按岗位发账号，不要所有人都用 `admin`。API 凭证和「库存不足时自动采购」只让负责人操作。

### 1.3 几个必须记住的概念

| 名词 | 解释 |
|---|---|
| TT 商品 | 在 TikTok Shop 卖家中心上架的商品。后台当前不负责创建 TikTok 商品。 |
| TT 商品中心 | 只读同步 TT 已上架商品，帮助运营少复制 `product_id` / `sku_id`，并检查哪些 SKU 还没有映射。 |
| SKU 映射 | 把 TT 的 `seller_sku` / `tts_sku_id` / `tts_product_id` 映射到内部 SKU 和面值。没有映射就不能自动发码。 |
| 内部 SKU | 我们自己的商品编码，例如 `STEAM-US-10`、`RAZER-US-50`。 |
| face_value | 卡密面值，单位美分。$10 填 `1000`。 |
| list_price | TikTok 售价，单位美分。用于调价倒挂预警。 |
| 供应商 | 分为手动供应商和 API 供应商。手动供应商线下给码；API 供应商可批量或实时取码。 |
| 采购单 PO | 采购成本和库存来源记录。手动采购必须先建 PO 再导入卡密。 |
| 卡密状态 | `free` 可售，`locked` 已被订单锁定，`used` 已发出，`void` 作废，`expired` 过期。 |
| 供应商采购 | API 供应商的下单记录，包含 WGCards 订单号、serviceOrder、状态和耗时。 |

## 2. 培训前准备

### 2.1 账号和登录

负责人先在 `用户管理` 给学员创建独立账号：

1. 进入 `用户管理` → 点「新增用户」。
2. 填用户名、初始密码、角色、显示名和备注。
3. 保持「启用账号」勾选，提交。
4. 把用户名和初始密码发给学员。

学员登录：

1. 打开后台入口。
2. 输入负责人提供的用户名和密码。
3. 登录后默认进入「看板」。

注意：

- 连续输错 5 次会锁定 15 分钟。
- 会话过期后会自动跳回登录页。
- 离职、实习结束或临时账号不用了，负责人要在 `用户管理` 停用账号。
- 业务培训时建议使用测试环境或测试商品，避免真实客户收到测试卡密。

### 2.2 上货前要准备的信息

每个新品至少准备下面这些信息：

| 信息 | 示例 | 来源 |
|---|---|---|
| 商品名称 | Steam Gift Card US $10 | 运营命名 |
| 内部 SKU | `STEAM-US-10` | 运营/采购统一命名 |
| TikTok seller_sku | `steam_us_10` | TikTok 卖家中心 |
| TikTok product_id | `1729...` | TikTok 商品详情或订单数据 |
| TikTok sku_id | `1730...` | TikTok 商品详情或订单数据 |
| 面值 | `1000` | 商品面值 |
| TikTok 售价 | `1199` | TikTok 售价 |
| 安全库存 | `20` | 低于多少张要补货 |
| 供应商 | 手动供应商或 API 供应商 | 采购 |
| 进价 | `900` | 采购成本，单位美分 |

`seller_sku`、`tts_product_id`、`tts_sku_id` 不一定全部都有，但建议尽量填全。TikTok webhook 里带哪个字段，系统就用哪个字段命中映射。

如果 `TT 商品中心` 已经能同步到该商品，优先从 `TT 商品中心` 点「去匹配」。系统会自动带入 TT 字段；只有未同步到或字段缺失时，才回 TikTok 卖家中心手动复制。

## 3. 上货流程：从 TikTok 上架到后台可履约

重要说明：**TikTok 商品上架在 TikTok Shop 卖家中心完成；Game Code Hub 后台负责建立映射、库存、采购和履约。**

### 3.1 TikTok 卖家中心上架

由运营在 TikTok Shop 卖家中心完成：

1. 创建虚拟商品。
2. 设置商品标题、图片、描述、类目、价格。
3. 设置 SKU，填写 seller_sku。
4. 保存并提交审核。
5. 记录 `seller_sku`、商品 ID、SKU ID 和售价。

培训重点：

- seller_sku 不要随意改，改了以后后台映射也要同步改。
- 同一个商品不同面值要用不同 SKU。
- 售价变动后，要同步更新后台 `list_price`，否则调价预警会失真。

### 3.2 TT 商品中心同步与 SKU 映射

入口：`TT 商品` → `同步 TT 商品` → 未匹配商品点「去匹配」；或进入 `SKU 映射` → `新建`

TT 商品中心重点：同步按钮、匹配统计、未匹配商品去映射。

![TT 商品中心](assets/business-training/annotated/02a-tts-products-list-annotated.png)

先在 TT 商品中心确认商品已经同步到后台，重点看：

- `seller_sku`、`product_id`、`sku_id` 是否和 TikTok 卖家中心一致。
- 匹配状态是不是「未匹配」或「已匹配」。
- 多面值商品每个面值是否都有单独的 TT SKU。

如果商品显示「未匹配」，点该行「去匹配」。这样新人不用手动到处复制 ID，也更不容易把多个面值混在一起。

现在从 `TT 商品中心` 点「去匹配」会直接跳到 `SKU 映射`。如果这组 TT 字段还没有映射，系统会打开新建弹窗并自动带入 `seller_sku`、`product_id`、`sku_id`、商品名和售价。新人只需要重点确认：

1. 内部 SKU 是否按公司命名规范填写。
2. 面额是否和 TikTok SKU 对应。
3. 安全库存是否合理。
4. 保存后是否还需要绑定 API 采购链接。

如果页面提示“这个 TT 商品已经有 SKU 映射”，不要重复新建。系统会筛出并打开已有记录：字段正确就保存；如果状态是 disabled，先确认该商品确实要重新销售，再勾选 `active` 保存。

SKU 列表重点：新增 SKU、核对 TT 字段、进入编辑。

![SKU 映射列表](assets/business-training/annotated/02-sku-mapping-list-annotated.png)

新建 SKU 重点：内部 SKU、面值/售价、TT 字段、保存。

![新建 SKU 映射](assets/business-training/annotated/03-sku-create-dialog-annotated.png)

填写字段：

| 字段 | 怎么填 | 培训提示 |
|---|---|---|
| `internal_sku_id` | 内部 SKU，例如 `STEAM-US-10` | 后续采购单和库存都按这个 ID 归类。 |
| `face_value` | 面值美分，例如 `$10` 填 `1000` | 面值和采购/卡密必须一致。 |
| `list_price` | TT 售价美分，例如 `$11.99` 填 `1199` | 用于调价倒挂锁库存。 |
| `product_name` | 商品名 | 看板和库存页更容易识别。 |
| `seller_sku` | TikTok 卖家 SKU | 建议必填。 |
| `tts_product_id` | TT 商品 ID | 有就填。 |
| `tts_sku_id` | TT SKU ID | 有就填，最稳。 |
| `safety_stock_threshold` | 安全库存阈值 | 低库存预警用。为空则用系统全局阈值。 |
| `active` | 勾选 | 下架或停卖时取消勾选。 |
| `锁库存` | 默认不勾 | 只有风险、调价倒挂、人工停卖时才勾。 |

保存后，到 SKU 列表确认：

- 商品名正确。
- 面值正确。
- `seller_sku` / `tts_product_id` / `tts_sku_id` 至少有一个能匹配 TikTok 订单。
- 如果要 API 采购，继续配置「API 采购链接」。

### 3.3 配置 API 采购链接

适用场景：

- 需要从 WGCards 等 API 供应商批量采购入库。
- 希望库存不足时，系统能为单个订单实时采购一张卡。

入口：`SKU 映射` → 找到目标 SKU → `编辑` → `API 采购链接`

API 链接重点：绑定外部 SKU、查看供应商实时库存；自动采购要先确认利润和风险。

![SKU API 采购链接](assets/business-training/annotated/03b-sku-api-link-editor-annotated.png)

商品目录重点：搜索商品、筛礼品卡、复制外部 SKU ID。

![供应商商品目录](assets/business-training/annotated/05c-supplier-catalog-annotated.png)

操作：

1. 选择 API 供应商。
2. 点击「浏览商品」，从供应商商品目录里选外部 SKU。
3. 系统会填入外部 SKU ID；固定面值商品通常会自动解析外部面值。
4. 如供应商是可变面值商品，手动填写外部面值。
5. 查看「供应商库存」：`不限` 表示供应商不限制库存；数字表示供应商实时可售数量；查询失败时先检查 API 凭证和外部 SKU。
6. 如要库存不足时自动采购，勾选「库存不足时自动采购」。
7. 点击「保存链接」。

注意：

- 批量 API 入库和实时自动采购，都必须先配置这个链接。
- 「库存不足时自动采购」只允许 `admin` 开启，普通采购/运营不要自行打开。
- 实时自动采购不会增加 `free` 可售库存，它只为当前订单买一张并直接锁给订单。
- 同一个 SKU 建议只保留一个实时自动采购供应商，避免采购来源混乱。
- API 供应商的币种要和供应商钱包币种一致。

## 4. 供应商建档

入口：`供货商`

供货商列表重点：区分手动/API，API 供应商可进入商品目录。

![供货商列表](assets/business-training/annotated/04-suppliers-list-annotated.png)

供应商分两种：

| 类型 | 适用场景 | 后续流程 |
|---|---|---|
| 手动采购 | 供应商通过聊天、邮件、文件发卡密 | 建采购单 → 收码 → 手动导入库存 |
| API 供应商 | 供应商提供 API，可自动下单取卡 | 配 API 凭证 → 绑定外部 SKU → API 批量入库或实时采购 |

### 4.1 新建手动供应商

操作：

1. 点击「新建供应商」。
2. 供应商类型选择「手动采购」。
3. 填名称、联系人、电话、默认账期、备注。
4. 保存。

手动供应商重点：填名称、选手动采购、创建。

![新建手动供应商](assets/business-training/annotated/05-supplier-create-manual-annotated.png)

培训提示：

- 名称必须唯一。
- 默认账期会用于采购单应付日期。
- 不再合作时不要删除，编辑后取消「启用」即可。
- 如果供应商还有未结清采购单，系统会拒绝禁用。

### 4.2 新建 API 供应商

操作：

1. 点击「新建供应商」。
2. 供应商类型选择「API 供应商」。
3. 填 API Host、App ID、Account ID、App Key、默认币种。
4. 保存。
5. 在供应商列表里进入「商品目录」，确认能拉到供应商商品。

API 供应商重点：选 API、填凭证、币种必须匹配钱包。

![新建 API 供应商](assets/business-training/annotated/05b-supplier-create-api-annotated.png)

培训提示：

- App Key 编辑时留空表示不修改。
- 默认币种必须和供应商 API 钱包币种一致。
- 商品目录支持按 SKU ID 和商品名搜索，也可以筛选「仅礼品卡」。
- API 凭证属于高风险配置，需要 `admin` 账号维护。

## 5. 手动采购入库流程

这是最基础、最容易培训的新手流程。

### 5.1 创建采购单

入口：`采购单` → `新增采购单`

采购单列表重点：手动新增 PO；API 走批量入库；日常看付款和批次状态。

![采购单列表](assets/business-training/annotated/06-purchases-list-annotated.png)

新增 PO 重点：供应商、SKU/面额、数量/进价。

![新增采购单](assets/business-training/annotated/07-purchase-create-dialog-annotated.png)

填写：

| 字段 | 说明 |
|---|---|
| PO 号 | 可留空，系统自动生成。也可填供应商外部单号。 |
| 供货商 | 选择已启用的手动供应商。 |
| `internal_sku_id` | 必须和 SKU 映射里的内部 SKU 一致。 |
| 面额 | 美分，例如 `$10` 填 `1000`。 |
| 数量 | 本次采购多少张卡。 |
| 单价 | 每张卡的采购成本，单位美分。 |
| 采购日期 | 默认今天。 |
| 到期日 | 可留空，系统按供应商账期自动计算。 |
| 备注 | 可写批次、活动、发票、供应商备注等。 |

系统会自动计算：

```text
采购总成本 = 数量 × 单价
```

### 5.2 收到卡密后导入库存

入口：`库存` → `卡密明细` → `导入卡密`

卡密明细重点：过滤查询、导入卡密、查看每张码状态。

![卡密明细](assets/business-training/annotated/09-inventory-codes-annotated.png)

导入卡密重点：选择 PO，上传供应商文件或粘贴卡密，确认数量后导入。

![导入卡密](assets/business-training/annotated/09b-inventory-import-dialog-annotated.png)

操作：

1. 选择刚才创建且未导入过的采购单。
2. 上传 `.txt` / `.csv` / `.tsv` / `.xlsx` 文件，或将供应商给的卡密粘贴到文本框，每行一张。
3. 确认系统解析出的卡密数量；Excel/CSV 会优先读取 `code`、`card_code`、`pin`、`卡密`、`兑换码`、`密码` 等列。
4. 有过期时间就填写，没有就留空。
5. 点击「导入」。
6. 系统返回导入成功数量、重复跳过数量和批次号。

如果供应商文件是旧版 `.xls`，先另存为 `.xlsx` 或 CSV。文件里“卡号”和“密码”分两列时，系统会合并成一行保存，例如 `AAAA-BBBB | 1234`。

卡密格式示例：

```text
AAAA-BBBB-CCCC-DDDD
EEEE-FFFF-GGGG-HHHH
FFFF-GGGG-HHHH-IIII
```

导入后检查：

1. 到 `库存` → `汇总`，确认对应 SKU 的 `free` 数量增加。
2. 到 `库存` → `批次`，确认批次关联了正确 PO。
3. 到 `采购单`，确认 PO 已出现 batch_id。

库存汇总重点：看 `free` 可售数量，低库存就补货。

![库存汇总](assets/business-training/annotated/08-inventory-summary-annotated.png)

注意：

- 同一张 PO 只能导入一次。
- 重复卡密会被跳过。
- 如果全部都是重复码，系统会回滚，本次不会入库。
- 前端不显示明文卡密，只显示状态和元数据。

### 5.3 记录付款

入口：`采购单` → 找到 PO → `记录付款`

操作：

1. 填本次付款金额，单位美分。
2. 填备注，例如流水号、付款渠道、付款人。
3. 保存。

付款状态：

| 状态 | 含义 |
|---|---|
| `unpaid` | 未付款 |
| `partial` | 部分付款 |
| `paid` | 已结清 |

注意：

- 已结清的 PO 不能再修改字段。
- 付款金额不能超过采购总成本。
- 财务月底对账时，以采购单和审计日志为准。

## 6. API 批量采购入库流程

适合 API 供应商，比如 WGCards。系统会自动向供应商下单取卡，并把卡导入库存。

### 6.1 前置条件

必须同时满足：

1. 已创建 API 供应商，并填好 API 凭证。
2. API 供应商处于启用状态。
3. 目标 SKU 已经建好 SKU 映射。
4. 目标 SKU 已在「API 采购链接」里绑定外部 SKU。
5. 供应商商品目录能搜索到该外部 SKU。

### 6.2 下单并入库

入口：`采购单` → `API 批量入库`

API 批量入库重点：选择已绑定 SKU，填数量和进价，下单入库。

![API 批量入库](assets/business-training/annotated/07b-api-bulk-dialog-annotated.png)

操作：

1. 选择已绑定 API 链接的 SKU。
2. 填采购日期。
3. 填数量。当前接口限制单次 `1-100` 张。
4. 填进价单价，单位美分。
5. 填备注。
6. 点击「下单并入库」。
7. 等待系统返回结果，通常需要 1-5 分钟。

成功后系统会自动：

1. 创建一张内部采购单 PO。
2. 向供应商下单。
3. 获取卡密。
4. 导入 `free` 库存。
5. 生成供应商采购记录。
6. 返回 WGCards 订单号、内部 PO、导入数量、批次号。

### 6.3 查看 API 采购结果

入口：`供应商采购`

供应商采购重点：看模式、状态、对账号、数量和耗时。

![供应商采购记录](assets/business-training/annotated/12-supplier-orders-annotated.png)

重点看：

| 字段 | 用途 |
|---|---|
| 模式 | `批量` 表示 API 批量入库，`实时` 表示订单触发自动采购。 |
| 状态 | `imported` / `shipped` 成功；`failed` / `timeout` 需要处理。 |
| 关联 PO | 批量采购可跳转到采购单；实时采购可跳转到订单。 |
| WGCards 订单号 | 与供应商对账用。 |
| serviceOrder | 我们传给供应商的订单标识。批量通常等于 PO 号，实时通常是 `TT-订单号-子单号`。 |
| SKU | 供应商外部 SKU。 |
| 数量 | 采购数量和实际返回卡数。 |

如果 API 批量采购失败：

1. 先看错误提示。
2. 到「供货商」检查 API 凭证和币种。
3. 到「商品目录」确认外部 SKU 是否仍存在、是否为礼品卡、是否有库存。
4. 到「SKU 映射」确认 API 采购链接是否绑定正确。
5. 修正后重新发起 API 批量入库。

## 7. 实时自动采购流程

实时自动采购是补救型能力：当订单来了，但是本地 `free` 库存不足，系统可以向 API 供应商实时买一张卡，然后直接发给该订单。

### 7.1 开启方式

入口：`SKU 映射` → 编辑目标 SKU → `API 采购链接`

勾选：

```text
库存不足时自动采购
```

### 7.2 系统怎么执行

订单来了以后：

1. 系统先查本地库存。
2. 如果有 `free` 卡，优先从本地库存取卡。
3. 如果没有 `free` 卡，但 SKU 配了实时自动采购，系统向 API 供应商买一张。
4. 买到卡后，直接锁给当前订单行。
5. 系统调用 TikTok 发码接口。
6. 成功后订单行变成 `shipped`，供应商采购记录变成 `shipped`。

注意：

- 实时采购不会补充可售库存，只服务当前订单。
- 实时采购会创建一张自动 PO，备注为 `auto-realtime`。
- 实时采购失败时，订单行会失败，原因通常是 `supplier_realtime_failed`。
- 实时采购适合作为兜底，不建议长期依赖它替代备货。

### 7.3 调价倒挂锁库存

对开启实时自动采购的 SKU，系统会定时比较：

```text
TikTok 售价扣除平台佣金后的净收入
vs
API 供应商实时采购价
```

如果净收入低于采购价，系统会：

1. 自动把 SKU 标记为「锁库存」。
2. 发送飞书告警。
3. 后续订单不会继续发货，失败原因会是 `inventory_locked`。

处理方式：

1. 检查 TikTok 售价是否太低。
2. 检查后台 `list_price` 是否和 TikTok 售价一致。
3. 检查供应商 API 价格是否涨价。
4. 调整售价或采购来源。
5. 确认利润安全后，在 SKU 映射里解除「锁库存」。

## 8. 订单履约流程

### 8.1 正常自动发货

买家在 TikTok 下单后：

1. TikTok 推送订单事件到系统。
2. 系统拉取订单详情。
3. 系统根据订单里的 `seller_sku` / `tts_sku_id` / `tts_product_id` 找 SKU 映射。
4. 系统从库存里锁定一张 `free` 卡密。
5. 系统调用 TikTok 虚拟商品发码接口。
6. 发码成功后：
   - 卡密状态变成 `used`。
   - 子单状态变成 `shipped`。
   - 订单详情页出现 fulfillment 日志。

运营日常只需要看：

- `订单` 列表有没有失败订单。
- `看板` 里待发货子单是否堆积。
- `库存` 是否低于安全库存。

### 8.2 订单详情怎么看

入口：`订单` → 搜订单号 → 点击订单号

订单列表重点：搜订单号；排障时勾「仅看失败」。

![订单列表](assets/business-training/annotated/10-orders-list-annotated.png)

订单详情重点：先看订单状态，再看子单状态和履约日志。

![订单详情](assets/business-training/annotated/11-order-detail-annotated.png)

重点检查：

| 区域 | 看什么 |
|---|---|
| 订单元信息 | 订单状态、金额、更新时间。 |
| 子单列表 | 每个 SKU 是否 `shipped`、`pending` 或 `failed`。 |
| 卡密 ID | 已发出的子单会关联卡密 ID。 |
| fulfillment 日志 | 看系统每次调用 TikTok 发码接口是否成功。 |

如果有失败子单，订单详情顶部会出现「处理建议」：

- `SKU 未映射`：点「去匹配 SKU」，系统带入订单里的 TT 字段，补内部 SKU 和面额后保存。
- `库存不足`：急单点「手动补码」直接粘贴 CDK 补发；常规缺货点「去补库存」，先手动采购/导入或 API 批量入库。
- `API 实时采购失败`：点「看供应商采购」，查看供应商返回的错误。

处理完原因后，再点右上角「重发」。不要在原因没修好时反复点重发。

### 8.3 常见失败原因和处理

| 失败原因 | 含义 | 处理方式 |
|---|---|---|
| `sku_not_mapped` | 订单 SKU 没有命中 SKU 映射 | 在订单详情点「去匹配 SKU」，补内部 SKU / 面额后再重发。 |
| `no_stock` | 没有可用卡密 | 急单在订单详情点「手动补码」粘贴 CDK 直接补发；常规缺货点「去补库存」，入库后再重发。 |
| `inventory_locked` | SKU 被锁库存 | 先查锁库存原因，确认价格/风险后再解除。 |
| `supplier_invalid` | API 供应商不可用或未配置 adapter | 检查供应商启用状态、API 凭证、SKU 链接。 |
| `supplier_realtime_failed` | 实时采购失败 | 在订单详情点「看供应商采购」，查供应商 API 状态。 |
| `manual_code_redeem_failed` | 手动补码已提交，但 TT 回传失败 | 看 fulfillment 日志，确认 TT 错误后重新补码或联系开发。 |
| TikTok API 报错 | 发码接口失败 | 看 fulfillment 日志，必要时联系开发。 |

### 8.4 手动补码

适用场景：

- 订单因为 `no_stock` 失败，但采购已经在线下拿到一张 CDK。
- 客服急需先把这单发掉，不想等完整采购单 + 入库流程。

入口：`订单` → 订单详情 → 失败子单旁边的「手动补码」

操作：

1. 点击「手动补码」。
2. 粘贴供应商给的 CDK。
3. 可选填写备注，例如客服工单号、供应商来源。
4. 点击「确认补发」。
5. 刷新后确认子单变成 `shipped`，fulfillment 日志里有 TT 回传记录。

注意：

- 手动补码会把这张 CDK 加密写入库存，并直接锁定到该子单；成功后状态变 `used`。
- 系统不会在审计日志里保存明文 CDK，只记录订单、子单、code_id 和备注。
- 如果这张 CDK 已经导入过，系统会拒绝，避免重复发码。
- 这是急救入口，不替代常规采购入库。常规补货仍然要走采购单和库存导入，方便财务对账。

### 8.5 手动重发订单

适用场景：

- 缺货导致失败，补货后重新发。
- SKU 映射缺失，补映射后重新发。
- 客服确认客户没收到码，需要重新尝试。

入口：`订单` → 订单详情 → `重发`

手动重发重点：写清原因，只点一次确认。

![手动重发](assets/business-training/annotated/11b-order-reship-dialog-annotated.png)

操作：

1. 填备注，例如「补库存后重发」「客户反馈未收到」。
2. 确认。
3. 等 3-10 秒刷新订单详情。
4. 看子单状态和 fulfillment 日志。

注意：

- 已经 `shipped` 的子单不会重复发。
- 同一订单连续点击两次重发，会创建两次重发任务。培训时提醒大家不要连点。
- 重发会写入审计日志。

### 8.6 取消和退货

| TikTok 状态 | 系统反应 | 业务动作 |
|---|---|---|
| `CANCELLED` | 未发的子单取消；已锁定未发的卡释放回库存；已发出的卡作废处理 | 一般无需人工操作，必要时抽查订单。 |
| `RETURN` | 系统记录退货状态；已发给客户的码无法回收 | 按平台售后规则处理，必要时客服补发新码。 |

## 9. 日常业务 SOP

### 9.1 每日开工检查

入口：`看板`

检查：

1. 今日订单数和 GMV 是否正常。
2. 待发货子单是否异常增多。
3. 今日失败子单是否为 0。
4. 低库存预警里是否有重点 SKU。
5. 最近失败订单是否需要处理。

建议节奏：

- 上午：看库存和失败订单，安排补货。
- 下午：复查 API 采购是否成功入库。
- 下班前：清掉可处理的失败订单，避免隔夜。

### 9.2 新品上货 SOP

```text
TikTok 卖家中心上架商品
  → TT 商品中心同步并核对 seller_sku / product_id / sku_id / 售价
  → 未匹配商品点「去匹配」，系统带入 TT 字段
  → 在弹窗里补内部 SKU、面额、安全库存并保存
  → 建供应商或确认已有供应商
  → 手动采购 PO 或配置 API 采购链接
  → 导入库存或 API 批量入库
  → 检查库存汇总 free 数量
  → 小单测试发货
  → 正式推广
```

上线前检查表：

- [ ] TikTok 商品已审核通过。
- [ ] TT 商品中心能同步到该商品。
- [ ] seller_sku / product_id / sku_id 与 SKU 映射一致。
- [ ] 面值 `face_value` 填对。
- [ ] 售价 `list_price` 填对。
- [ ] 安全库存填好。
- [ ] 采购单或 API 链接已准备。
- [ ] 库存 `free` 数量大于首日预估销量。
- [ ] 未勾选不必要的「锁库存」。
- [ ] API 自动采购 SKU 已确认不会倒挂。

### 9.3 手动采购 SOP

```text
确认补货 SKU 和数量
  → 向供应商下单
  → 后台创建采购单
  → 收到卡密文件
  → 库存页卡密明细导入卡密
  → 检查导入数量和重复数量
  → 检查库存汇总
  → 财务按账期记录付款
```

### 9.4 API 批量采购 SOP

```text
确认 SKU 已绑定 API 外部 SKU
  → 采购单页点击 API 批量入库
  → 选择 SKU、数量、进价单价
  → 下单并等待入库
  → 到供应商采购页确认状态 imported
  → 到库存汇总确认 free 增加
  → 到采购单确认 PO 和成本
```

### 9.5 供应商后台手动下单 SOP

当前系统可以通过 WGCards API 查看供应商历史订单、订单详情和卡密，但还没有上线“一键把供应商后台手动下的订单导入为内部采购单并入库”的完整页面。

临时处理方式：

```text
在供应商后台手动下单
  → 等供应商发卡
  → 下载/复制卡密文件
  → 后台创建手动采购单
  → 库存页导入卡密
  → 在采购单备注写供应商订单号
  → 财务对账时用备注里的供应商订单号核对
```

待办优化：

- 在 `供应商采购` 页增加“同步供应商历史订单”。
- 选择供应商订单后，自动拉订单详情和卡密。
- 让采购选择内部 SKU / PO / 成本后，一键导入库存。

### 9.6 客诉未收到码 SOP

```text
客服拿到 TikTok 订单号
  → 订单页搜索订单
  → 进入订单详情
  → 看子单状态和 fulfillment 日志
  → 如果 failed，按失败原因处理
  → no_stock 急单可点手动补码；常规缺货先补库存
  → 补库存/补映射/解除锁库存后点击重发
  → 刷新确认 shipped
  → 在客服工单里记录处理结果
```

### 9.7 内容创作素材采集 SOP

入口：`内容创作` → `素材采集`

推荐顺序：

```text
先选对应游戏
  → 优先上传本地视频文件
  → 必要时再粘贴 URL 抓取
  → 看最近采集里的状态和进度
  → 已完成后去素材库复核片段
  → 有真人/不合适片段先标记或删除
```

培训重点：

- 本地上传最稳定，适合 TikTok、YouTube、Steam 预告片等已经下载好的文件。
- YouTube 是正式素材来源，但生产环境要配置 YouTube cookies；没配 cookies 时可能被要求登录或人机验证。遇到格式不可用时先点「重试」，仍失败再让管理员更新素材服务。
- Steam 商品页会优先尝试抓取官方 trailer；如果该商品没有 trailer，按页面提示改用本地上传或换有预告片的 Steam 商品页。
- 状态显示 `处理中` 时，看进度阶段：下载视频、清理画面、识别语音、切分镜头、智能打标。长视频处理几分钟是正常的。
- 状态显示 `失败` 时，先看红色错误提示。修正链接/文件后点「重试」，不要反复提交同一批无效链接。
- 素材入库后才会进入 `素材库`，后续生成脚本和成片都从素材库选片。

常见处理：

| 看到什么 | 原因 | 怎么办 |
|---|---|---|
| YouTube 要求登录或人机验证 | 服务器没有可用 YouTube cookies，或 cookies 过期 | 让管理员更新 `/data/workflow/cookies/youtube.txt` 并重启 workflow；急单先本地上传。 |
| YouTube 格式不可用 | YouTube 当前没有返回系统优先选择的视频格式，或 yt-dlp 解析版本过旧 | 先点「重试」；仍失败时让管理员更新素材服务，急单先本地上传。 |
| Steam 页面没有可抓取视频 | 商品页没有 trailer，或 Steam 没返回 hls/dash 视频源 | 换有预告片的 Steam 商品页，或本地上传。 |
| 普通页面没有可抓取视频 | 粘贴的是商品页/落地页，不是视频直链 | 换成具体视频链接，或本地上传。 |
| 一直停在处理中 | 正在跑视频处理，或旧任务失败状态未同步 | 先看进度和任务监控；超过 30 分钟无变化再找开发。 |
| 失败后还有旧片段 | 上一次处理只成功了一部分 | 点「重试」会清掉该素材旧片段并重新处理。 |

### 9.8 月度对账 SOP

入口：`财务`、`采购单`、`供应商采购`、`审计日志`

财务重点：看 GMV、毛利、应付和逾期应付。

![财务概览](assets/business-training/annotated/13-finance-overview-annotated.png)

审计重点：按操作者/动作过滤，查谁做了什么。

![审计日志](assets/business-training/annotated/14-audit-log-annotated.png)

步骤：

1. 在 `财务` 看本月 GMV、已售卡密成本、毛利、应付、逾期应付。
2. 在 `采购单` 过滤未结清 PO。
3. 核对供应商账单，尤其是 API 供应商的 WGCards 订单号和 serviceOrder。
4. 对已付款的 PO 记录付款。
5. 用 `审计日志` 过滤 `purchase_pay`，确认付款操作完整。
6. 对异常成本、重复采购、失败采购整理清单给负责人。

## 10. 培训演练安排

建议业务培训按 90 分钟组织。

### 10.1 第一段：系统认知，15 分钟

演示：

1. 登录后台。
2. 介绍左侧菜单。
3. 解释 SKU 映射、采购单、库存、订单之间的关系。

学员要会回答：

- 为什么没有 SKU 映射会发货失败？
- 为什么采购单是库存成本源头？
- `free`、`locked`、`used` 分别是什么意思？

### 10.2 第二段：手动采购完整演练，25 分钟

练习：

1. 新建一个手动供应商。
2. 从 TT 商品中心点「去匹配」新建一个 SKU 映射。
3. 创建采购单。
4. 导入 3 张测试卡密。
5. 到库存汇总确认 `free=3`。
6. 记录一次部分付款。

验收：

- 学员能解释 PO、批次、库存数量之间的关系。
- 学员知道同一张 PO 只能导入一次。

### 10.3 第三段：API 采购演练，20 分钟

练习：

1. 查看 API 供应商商品目录。
2. 在 SKU 映射里绑定外部 SKU。
3. 发起 API 批量入库。
4. 到 `供应商采购` 查看状态。
5. 到 `库存` 查看入库结果。

验收：

- 学员知道 API 批量入库失败时先查哪几个地方。
- 学员知道实时采购不会增加 `free` 库存。

### 10.4 第四段：订单异常演练，20 分钟

练习：

1. 找一个失败订单。
2. 识别失败原因。
3. 使用订单详情顶部「处理建议」选择动作：手动补码、补库存、补映射、解除锁库存、查供应商采购。
4. 如果是 `no_stock` 急单，演练一次「手动补码」；如果是常规缺货，补库存后点击重发。
5. 刷新看 fulfillment 日志。

验收：

- 学员能根据 `sku_not_mapped`、`no_stock`、`inventory_locked` 做正确处理。
- 学员知道 `no_stock` 有两条路：急单手动补码，常规缺货补库存后重发。
- 学员知道不要连续点击重发。

### 10.5 第五段：财务和审计，10 分钟

演示：

1. 财务页看应付和毛利。
2. 采购单记录付款。
3. 审计日志查操作记录。

验收：

- 学员知道所有写操作都能在审计日志追溯。
- 学员知道已结清 PO 不能再改。

## 11. 常见问题

### Q1：后台能直接给 TikTok 上架商品吗？

不能。TikTok 商品上架在 TikTok Shop 卖家中心完成。后台做的是 SKU 映射、采购、库存、履约。
后台的 `TT 商品中心` 只是只读同步已上架商品，方便少手填 ID，不会创建、改价或上下架 TikTok 商品。

### Q2：为什么订单失败 `sku_not_mapped`？

订单里的 TikTok SKU 字段没有命中后台 SKU 映射。优先在订单详情点「去匹配 SKU」，系统会带入订单里的 TT 字段；补内部 SKU 和面额后，再回订单详情重发。

### Q3：为什么我导入了卡密，订单还是缺货？

检查三点：

1. 导入的 PO 里的 `internal_sku_id` 和订单 SKU 映射是否一致。
2. 面值是否一致。
3. 库存状态是否为 `free`，而不是 `locked`、`used`、`void`、`expired`。

### Q4：API 批量采购成功，但库存没增加怎么办？

到 `供应商采购` 看状态和错误信息。如果供应商返回卡密但导入为 0，可能是重复卡密。再到 `库存` 按批次或 SKU 查。

### Q5：什么时候应该开启实时自动采购？

适合高优先级 SKU 或偶发缺货兜底。不要把实时采购当成主要备货方式，因为它依赖供应商 API 的实时稳定性和价格。

### Q6：为什么 SKU 被锁库存？

常见原因是调价倒挂：TikTok 售价扣佣后低于 API 供应商采购价。先检查售价、后台 `list_price`、供应商价格，确认利润安全后再解除。

### Q7：客户说没收到码，可以直接重发吗？

先看订单详情和 fulfillment 日志。如果子单已经 `shipped`，要先确认平台是否真的未展示或客户是否看错。必要时再重发，并写清备注。

### Q8：卡密明文在哪里看？

前端默认不展示明文，卡密加密存储。正常业务不要直接查看明文；客服需要明文时按单独授权流程处理。

## 12. 业务红线

1. 不要在真实店铺用测试卡密。
2. 不要随意修改 seller_sku；改了必须同步 TT 商品中心并更新后台映射。
3. 不要在没确认利润的情况下开启实时自动采购。
4. 不要连续点击订单重发。
5. 不要作废已经发给客户的 `used` 卡密。
6. 不要删除或禁用仍有未结清 PO 的供应商。
7. 不要把采购成本填成 TikTok 售价。
8. 不要忽略低库存和失败订单，虚拟商品履约延迟会直接影响店铺体验。

## 13. 一页速查

### 新品上架

```text
TT 卖家中心上架 → TT 商品中心同步 → 去匹配 → SKU 映射 → 供应商 → 采购/入库 → 库存确认 → 测试单 → 开卖
```

### 手动采购

```text
采购单 → 收卡密 → 库存导入 → 检查 free → 记录付款
```

### API 批量采购

```text
API 供应商 → 商品目录 → SKU API 链接 → API 批量入库 → 供应商采购 → 库存确认
```

### 订单失败

```text
订单详情 → 看处理建议 → 修复原因 → 重发 → 看 fulfillment 日志
```

### 对账

```text
财务 → 采购单 → 供应商采购 → 审计日志
```
